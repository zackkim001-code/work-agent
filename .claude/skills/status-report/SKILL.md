# status-report

노션 기록만 근거로 답한다. 확인대기 데이터는 확정처럼 쓰지 않는다.

## 절차

1. **질문 해석**: 대상 프로젝트·스레드, 기간(기본: 전체, "지난주"·"이번 달" 등이 있으면 그 범위), 원하는 관점(히스토리 / 현재 / 할 일 / 전부).
   - 대상이 모호하면 되묻는다: "서브원 쪽인가요, MRO 쪽인가요?" — 단, 최근 대화에서 명백하면 묻지 않는다.
2. **조회** (`notion-store` rows 모드):
   - 프로젝트 페이지 (`현재 상황`, `현황 갱신일`)
   - 해당 프로젝트 확정 로그, 기간 내, `날짜` 내림차순 (스레드 지정 시 텍스트로 거른다)
   - 열린 할 일 (열림·진행·보류), 명시/추정 구분
   - 확인대기·장기대기 로그 건수 (내용은 읽지 않는다)
   - 열린 상충
3. **구성** (산문 위주, 불릿은 할 일에만):
   1. **히스토리** — 시간순 핵심 결정과 전환점. 로그 날짜를 괄호로 붙인다. 진행 세부는 생략하고 결정·이슈 중심.
   2. **현재 상황** — 프로젝트 `현재 상황` 필드를 기준으로, 최신 로그와 다르면 최신 로그를 우선.
   3. **해야 할 일** — 명시 먼저, 추정은 "(추정)"과 근거를 붙여 아래에. 기한이 있으면 D-n.
   4. **확인 대기** — "수집돼 확인을 기다리는 항목 N건 (반영 전이라 위 내용에 포함하지 않음)". 0건이면 생략.
   5. **미해결 상충** — 있으면 "○월○일 '~'와 ○월○일 '~'가 다름. 어느 쪽이 맞는지 알려주면 정리함".
4. **자기 검증**: 답변의 모든 사실 문장이 조회한 확정 로그 또는 `현재 상황` 필드로 추적되는가. 추적 안 되는 문장은 지운다. 기록이 없으면 "기록 없음"이라고 쓴다.

## 출력 길이

- 기본: 프로젝트 하나에 200~400자. "자세히"가 붙으면 제한 없음.
- "한 줄로"가 붙으면 현재 상황 한 문장 + 할 일 건수.

## 금지

- 확인대기 내용을 답변에 섞지 않는다.
- 로그에 없는 인과·전망을 덧붙이지 않는다. 필요하면 "(기록 기준 추정)"을 명시.
