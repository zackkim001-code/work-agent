# brief-prep

노션만 읽고 쓴다. 산출물은 브리핑 DB의 오늘 페이지 하나. morning 스킬은 **빈 섹션을 조용히 버리므로** 실패해도 반드시 문구를 남긴다.

시각은 KST 기준. 주말(토·일)에는 실행하지 않는다 — 프롬프트가 주말에 호출되면 "주말 — 브리핑 없음"만 남기고 종료.

## C0. 후처리

1. `수정요청` 로그: `수정 메모`를 항목에 적용해 `확정`으로. 적용 불가는 `확인대기`로 되돌리고 메모 끝에 "(적용 불가: 사유)". `메모 대기=true`인데 메모가 비어 있으면 `확인대기`로 되돌린다.
2. 할 일 후보 전환: `상태=확인대기`인 할 일의 `출처 로그` 상태를 보고 — 확정이면 `열림`(`최근 언급일` 오늘), 제외면 `제외`. 출처 로그가 아직 확인대기면 그대로.
3. 장기대기: `확인대기` 로그 중 `대기일수 > 5` → `장기대기`.
4. 현황 요약 재생성: `현황 갱신일`이 그 프로젝트의 가장 최근 확정 로그 `날짜`보다 **이전**인 프로젝트만. `현재 상황` 3~5문장 덮어쓰기. 갱신일이 최근 로그 날짜와 같거나 더 새로우면 건드리지 않는다 (A4가 기록 직후 이미 갱신했으므로 매일 다시 쓸 이유가 없다. 2026-09-22 테스트에서 확인). 로그가 하나도 없는 프로젝트는 "기록 없음"으로 두고 넘어간다.

각 단계는 실패해도 다음 단계로 간다. 실패는 브리핑 페이지 "준비 상태" 섹션에 적는다.

## C1. 미완료 과제 수집

할 일 DB에서 `상태 ∈ {열림, 진행, 보류}` 조회 → 프로젝트 이름 역매핑 → JSON 배열로 `scripts/task_metrics.py` 에 넣는다. 0건도 정상.

실패 시 1회 재시도. 재실패면 브리핑 페이지에 "과제 조회 실패 — 오늘 과제 목록 없음"을 쓰고 `준비 상태=과제 조회 실패`.

## C2. 우선순위·처리 방법

입력: `today_candidates`, `stale`, 프로젝트 `현재 상황`, 운영 기준 페이지의 역할·권한 요약, 열린 상충.

- 오늘 다룰 과제를 고른다 (최대 7건). 기준: 기한 경과·임박 → 나 때문에 막힌 사람 → 방치 → 미해결 상충 관련.
- 과제마다 처리 방법 1~2문장: 누구에게 무엇을, 어떤 순서로, 전결 기준상 누구 결재인지. 역할·권한 요약이 비어 있으면 결재 부분은 생략하고 "(역할 요약 없음)"을 붙인다.
- 명시 → 추정 순. 추정에는 "(추정)"과 근거.
- 할 일 페이지의 `처리 방법` 속성도 같은 문장으로 갱신한다.

자기 검증: 처리 방법이 역할·권한 요약과 모순되는가 / 명시·추정 구분이 유지됐는가. 실패 시 1회 재시도, 재실패면 처리 방법 없이 목록만 싣고 `준비 상태=처리 방법 생략`.

## C3. 주간보고 초안 (월요일만)

`weekly-report` 스킬을 호출한다. 결과 페이지 URL을 브리핑 페이지 `주간보고` 속성과 본문에 넣는다. 실패하면 "주간보고 초안 생성 실패"를 본문에 쓰고 `준비 상태=주간보고 실패`.

## C4. 브리핑 페이지 작성

브리핑 DB에 `제목 = 브리핑 YYYY-MM-DD`, `날짜`, `준비 상태` 로 생성. 같은 날짜 페이지가 이미 있으면 본문을 교체하되, **"전달 기록" 섹션이 있으면 그대로 보존**한다 (06:00 brief-deliver가 이 섹션으로 중복 발송을 막는다. 지우면 재실행 시 카톡이 두 번 간다). 본문 구조 (섹션 제목은 정확히 이대로 — morning의 Sections 항목과 일치해야 한다):

```
## 오늘 처리할 업무 과제
1. **[명시] 영향 보고서 제출** — D-1 · 유류·포장재 › 영향 보고
   처리: 재무팀 ○○에게 인상률 표 확인받고 팀장 결재 상신. 전결: 팀장.
   근거: 9/16 로그 "팀장이 금요일까지 요청"
2. **[추정] A사 선정 통보** — 근거: 선정 후 통보가 남았음
   ...

## 방치 과제
- MRO 대시보드 요구사항 정리 — 최근 언급 21일 전

## 미해결 상충
- 유류 › 견적 검증: 9/10 "B사 유력" ↔ 9/17 "A사 선정". 어느 쪽이 맞는지 알려주면 정리함.

## 주간보고 초안        ← 월요일만
[링크] 핵심 요약 3줄

## 준비 상태
정상 · 확인대기 4건 (내용은 반영 전) · 장기대기 1건

## 송출용 요약        ← 06:00 brief-deliver가 카카오톡 본문으로 씀. 링크 제외 120자 이내
[브리핑 9/22 화] 과제 3건(명시 2·추정 1) · 방치 1 · 상충 0
1순위: 영향 보고서 팀장 결재 상신
2: A사 선정 통보 (추정)

## 낭독 대본          ← 06:00 brief-deliver가 듣기 페이지 본문으로 씀. 600~900자
9월 22일 화요일 브리핑입니다. 오늘 처리할 과제는 세 건입니다.
첫째, 유류·포장재 단가인상 영향 보고서. 기한이 내일입니다. 재무팀 확인을 받아 팀장 결재로 올립니다.
둘째, A사 선정 통보. 추정입니다. 선정 뒤 통보가 남아 있어서 넣었습니다.
방치된 과제가 한 건 있습니다. MRO 대시보드 요구사항 정리, 3주째 언급이 없습니다.
미해결 상충은 없습니다. 확인 대기 4건은 아직 반영 전입니다. 이상입니다.
```

- 내용이 없는 섹션은 "해당 없음"이라고 쓴다 (빈 채로 두면 morning이 섹션을 버린다).
- 금액·단가는 "오늘 처리할 업무 과제"~"준비 상태" 섹션에는 필요하면 싣는다 (Cowork 안에서만 렌더된다). **단, "송출용 요약"과 "낭독 대본"에는 싣지 않는다.** 이 둘은 카카오톡과 듣기 페이지로 회사 PC 밖에 나간다.

### 송출용 요약·낭독 대본 작성 규칙 (설계 8.4)

- 공통: 금액·단가·인상률 수치·계약 조건·계좌·연락처를 싣지 않는다. 항목명만 쓴다 ("인상률 확인"). 업체명은 이니셜(A사). 확인대기는 건수만. 링크·ID를 넣지 않는다. 쓰기 전에 `notion-store/scripts/validate_entry.py --outbound`로 검사한다 (요약 `--max 200 --max-urls 0`, 대본 `--max 1200 --max-urls 0`). 위반 문장은 고쳐 쓴다.
- 송출용 요약: 첫 줄 `[브리핑 M/D 요일] 과제 N건(명시 a·추정 b) · 방치 c · 상충 d`. 이어서 `1순위: <과제 제목>`, `2: <과제 제목>` 최대 2줄 (추정이면 `(추정)`). 월요일은 마지막 줄 `주간보고 초안 준비됨`. 링크 제외 120자 이내. 과제가 0건이면 첫 줄만 쓴다.
- 낭독 대본: 600~900자. 들어서 이해되는 순서로 쓴다: 날짜 인사 → 과제 수 → 과제별 (제목, 왜 오늘인지, 처리 방법 한 문장. 추정이면 "추정입니다") → 방치 과제 → 미해결 상충 → 확인대기 건수 → "이상입니다". 번호·기호·표·괄호 약어를 쓰지 않는다 (음성으로 읽힌다). 과제당 두 문장 이내. C2가 실패했으면 과제 제목만 읽는다. 월요일은 끝에 "주간보고 초안이 준비됐습니다" 한 문장을 붙인다.
- 준비 상태가 실패(과제 조회 실패 등)여도 두 섹션은 반드시 쓴다. 이때 요약 첫 줄에 "과제 조회 실패"를 넣고, 대본은 그 사실과 확인대기 건수만 읽는다.
- **낭독 대본 (영어)**: 낭독 대본 바로 뒤에 `## 낭독 대본 (영어)` 섹션으로 같은 내용의 영어 번역을 쓴다 (듣기 페이지의 English 전환용, 2026-09-22 추가). 같은 송출 규칙. 회사 고유명사는 그대로(ServeOne, Miryang plant, P3), 고객사는 "customer Z"처럼 이니셜. 부서명은 SQ team, Legal, Purchasing 식으로. 숫자 읽기가 자연스럽게 "September 30", "126 pallets". 영어 대본을 쓰지 못하면 섹션을 생략한다 — brief-deliver가 한국어만 만든다.
- 이 두 섹션은 C5의 Sections에 넘기지 않는다 (morning 페이지에는 나오지 않는다).

## C5. morning 스킬로 넘기기

같은 예약 작업 안에서 이어서 `/morning`을 호출하며 다음 형식으로 전달한다:

```
Sections:
- 오늘 처리할 업무 과제: 노션 페이지 <브리핑 페이지 URL>의 "오늘 처리할 업무 과제"·"방치 과제"·"미해결 상충" 섹션
- 주간보고 초안: 같은 페이지의 "주간보고 초안" 섹션   ← 월요일만
언어: 한국어
```

Microsoft 365 커넥터가 이 계정에서 막혀 있는 동안 morning의 일정·메일 섹션은 자동으로 생략된다. 그래도 위 Sections는 렌더된다. "송출용 요약"과 "낭독 대본"은 Sections에 넣지 않는다 — 06:00 brief-deliver 전용이다.
