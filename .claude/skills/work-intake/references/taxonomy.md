# 분류 체계

## 프로젝트와 스레드

| 프로젝트 | 초기 스레드 | 이런 말이 나오면 |
|---|---|---|
| 서브원 재고관리 | VMI 운영 / 불용재고·폐기 처리 (구형 BUSH 폐기·비용회수 포함) | 서브원, VMI, 재고, 불용, 폐기, BUSH, 비용회수 |
| MRO·일반자재 단가·업체 관리 | 단가·업체 관리 / 공장별 일반자재 구매기준 정리 / MRO 구매현황 대시보드 | MRO, 일반자재, 단가표, 업체 등록·평가, 구매기준, 대시보드 |
| 유류·포장재 단가인상 | 견적 검증·협상 / 결재 / 영향 보고 | 유류, 경유, 그리스, 포장재, 박스, 단가인상, 인상률, 견적, 협상 |
| 미분류 | — | 위 어디에도 맞지 않을 때 |

- 새 스레드는 **기존 스레드에 맞지 않는 주제**가 나올 때 가장 가까운 프로젝트 아래 바로 만든다. 묻지 않는다. 사후 요약에 "새 스레드"로 표시한다.
- 스레드 이름은 명사구 2~6단어. 프로젝트 이름을 반복하지 않는다.
- 어느 프로젝트에도 맞지 않으면 `미분류` 프로젝트, 스레드는 비운다.

## 로그 유형

| 유형 | 정의 | 예 |
|---|---|---|
| 진행 | 어떤 일이 어디까지 됐다는 사실 | "견적서 3개 업체에서 받았어" |
| 결정 | 확정된 선택·합의 | "포장재는 A사로 가기로 했어" |
| 이슈 | 막힘, 문제, 위험 | "서브원 쪽에서 재고 데이터가 안 맞는대" |
| 요청 | 누가 누구에게 무엇을 해달라고 한 것 | "팀장님이 영향 보고서 금요일까지 달래" |
| 메모 | 위에 안 들어가는 맥락·참고 | "B사 담당자 바뀜" |

한 발화에 여러 사실이 있으면 사실마다 한 항목. "견적 받았고, A사로 정했고, 팀장이 보고서 달래" → 진행 1, 결정 1, 요청 1.

## 명시 할 일 vs 추정 할 일

**명시**: 사용자가 해야 한다고 직접 말했거나, 메일·메시지에서 본인에게 명시적으로 요청된 일.
- "내가 ~해야 해", "~하기로 했어", "~해달래", "~까지 보내야 해"
- 기한이 언급되면 `기한`에 넣는다. "금요일까지"는 이번 주 금요일 날짜로 환산한다.

**추정**: 맥락상 다음 단계라고 에이전트가 추론한 일. **근거 한 줄 필수.**
- 근거 형식: "~라고 했으므로 다음은 ~일 것" / "결정 후 통보가 남았음"
- 추정은 보수적으로. 한 발화에서 추정 할 일은 최대 2건.
- 기각된 추정(할 일 DB `상태=기각`, `기각 근거` 있음)과 같은 근거로는 다시 만들지 않는다. 기록 전에 기각 목록을 한 번 본다.

## 완료 매칭

"~했어", "~끝났어", "~보냈어"가 열린 할 일과 같은 대상을 가리키면 그 할 일을 `완료`로 바꾼다. 새 할 일을 만들지 않는다. 대상이 두 개 이상 맞으면 가장 최근 언급된 것 하나만 바꾸고 사후 요약에 표시한다.

## 신규 / 중복 / 상충 판정

같은 스레드의 최근 30일 확정 로그와 비교한다.

- **중복**: 같은 사실을 다시 말한 것. 새 기록 없이 기존 항목 `최근 언급일`만 오늘로 갱신.
- **상충**: 같은 대상에 대해 이전 확정 기록과 모순. 예: 지난주 "A사로 확정" → 오늘 "아직 업체 못 정했어". 기록하되 `판정=상충`, `상충 대상`에 이전 항목 연결. 멈추고 묻지 않는다.
  - 이번 기록이 같은 스레드의 열린 상충을 정리하는 내용이면, 그 이전 상충 항목의 `상충 해소 기록`에 이번 entry_id를 적는다.
- **신규**: 그 외.
