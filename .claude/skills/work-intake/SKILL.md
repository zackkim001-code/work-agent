# work-intake

자유 텍스트 → 항목 배열 → 노션 기록 → 사후 요약. 확인 없이 즉시 기록하고 사후 요약으로만 알린다. 분류 규칙은 `references/taxonomy.md`, 노션 접근은 `notion-store` 스킬을 따른다.

## 발동 기준

- 세 프로젝트·구매 업무와 관련된 사실·결정·요청·할 일이 담긴 발화 → 발동.
- 코딩·일반 질문·잡담 → 발동하지 않는다.
- 애매하면 기록하되 사후 요약 첫 줄에 "기록함 — 아니면 '기록 취소'"를 붙인다.
- 발화에 "기록하지 마"가 있으면 발동하지 않는다.
- 질문("어떻게 돼가?")은 status-report, 역할·규정 질문("이거 내가 해야 해?")은 work-guide다. 한 발화에 사실과 질문이 섞여 있으면 사실은 기록하고 질문에는 답한다.

## 절차

### A1. 분해·분류

입력: 사용자 메시지, 프로젝트 목록(스레드 포함), 열린 할 일 목록, 기각된 추정 목록.

1. 메시지를 사실 문장 단위로 쪼갠다.
2. 문장마다 프로젝트·스레드·유형을 지정한다. 기존 스레드에 맞지 않으면 새 스레드를 만든다. 어느 프로젝트에도 안 맞으면 `미분류`.
3. 할 일을 뽑는다: 명시 / 추정(근거 1줄). 완료 언급은 열린 할 일에 매칭한다.
4. 항목마다 `원문 발췌`에 해당 문장을 그대로 넣는다.

자기 검증 (기록 전에 반드시):
- 원문의 사실 문장 중 어느 항목에도 안 들어간 것이 있는가? → 있으면 추가.
- 원문에 없는 사실을 만들어 넣었는가? → 있으면 삭제.
- 모든 추정 할 일에 근거가 있는가?

실패(검증 통과 못 함) 시 1회 재시도. 재실패 시 메시지 전체를 `미분류` 프로젝트, 유형 `메모`, 원문 1건으로 기록하고 사후 요약에 "분류 실패, 정정 필요"를 표시한다. 기록은 잃지 않는다.

### A2. 상충·중복 검사

해당 스레드의 최근 30일 확정 로그를 조회해 항목마다 신규/중복/상충을 판정한다 (`taxonomy.md` 기준). 조회에 실패하면 판정 없이 `신규`로 기록하고 사후 요약에 "상충 검사 생략"을 표시한다.

### A3. 노션 기록

`notion-store` 쓰기 절차대로: entry_id 부여 → `validate_entry.py --kind log` / `--kind task` → 기존 entry_id 조회 → 생성 → `--check` 대조.

- 로그: 상태 `확정`, 출처 `직접입력`, 날짜는 오늘(사용자가 다른 날을 말하면 그 날).
- 할 일: 신규는 `열림`, `최근 언급일` 오늘. 완료 매칭은 기존 항목 `상태=완료`.
- 새 스레드: 프로젝트 `스레드` 텍스트에 한 줄 추가.

### A4. 현황 요약 갱신

영향받은 프로젝트마다 `현재 상황`을 최근 확정 로그 기준 3~5문장으로 다시 쓴다. 문장마다 근거 로그가 있어야 한다. 실패하면 건너뛰고 사후 요약에 "현황 요약 미갱신"을 표시한다 (다음 05:00 후처리에서 재생성).

### A5. 사후 요약

형식 (짧게, 프로젝트별):

```
기록 완료 — 유류·포장재 단가인상 › 견적 검증·협상
  · [진행] 3개 업체 견적 수령
  · [결정] 포장재 A사 선정  ⚠ 상충: 9/10 "B사 유력" 기록과 다름
  · 할 일(명시) 영향 보고서 금요일까지 → 기한 9/25
  · 할 일(추정) A사에 선정 통보 — 근거: 선정 후 통보가 남았음
🆕 새 스레드: MRO·일반자재 › 안전용품 단가
❓ 미분류 1건: "다음 주 출장" — 어느 프로젝트?
```

- 새 스레드, 상충, 추정 할 일, 미분류는 눈에 띄게.
- 운영 기준 페이지에 역할·권한 요약이 있고, 기록한 항목이 요약상 내 몫이 아닌 것으로 보이면 한 줄만 붙인다: "ℹ 업무분장상 ○○팀 소관으로 보임".
- 정정: "그건 유류 쪽이야", "그거 추정 아니고 확정이야", "기록 취소" 같은 말이 오면 해당 항목의 속성을 고치고(취소는 상태 `제외`) 현황 요약을 다시 갱신한다. 되묻지 않는다.

## 수집분·수정 메모에 재사용할 때

- inbox-harvest(B2): 같은 A1·A2 규칙. 단 출처 `Outlook|Teams`, 상태 `확인대기`, `출처 참조` 필수, 할 일은 `확인대기` + `출처 로그`.
- brief-prep(C0): `수정요청` 항목의 `수정 메모`를 항목에 적용한다. 메모가 항목을 어떻게 고치라는지 해석이 안 되면 `확인대기`로 되돌리고 `수정 메모` 끝에 "(적용 불가: 사유)"를 덧붙인다.
