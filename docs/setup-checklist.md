# 운영 개시 체크리스트 (사용자가 직접 하는 일)

2026-09-22 기준. 코드·스킬·노션 구조는 준비돼 있고, 아래는 계정 권한이 필요해 Claude가 대신 할 수 없는 일이다. 순서대로 하면 된다. 예상 소요 30~40분.

## 1. 스킬 3개를 Claude 계정에 올린다 (10분)

파일 위치: `프로젝트3\work-agent\dist\`

| 파일 | 할 일 | 이유 |
|---|---|---|
| `brief-deliver.zip` | **신규 업로드** | 06:00 전달 스킬. 계정에 아직 없음 |
| `brief-prep.zip` | **기존 것 삭제 후 재업로드** | 송출용 요약·낭독 대본·영어 대본 규칙, 현황 요약 조건, 전달 기록 보존이 추가됨 |
| `notion-store.zip` | **기존 것 삭제 후 재업로드** | `--outbound` 송출 검사, 전달 채널·전달 기록 규칙, 스키마 갱신 |
| `weekly-report.zip`, `work-intake.zip` | 계정에 없으면 업로드 | 09-19에 만든 zip도 백슬래시 경로였으므로 아직 올라간 적이 없을 가능성이 크다. 스킬 목록에 없으면 같이 올린다 |

zip은 반드시 `dist\make_zips.py`로 만든다 (PowerShell Compress-Archive로 만든 zip은 경로에 백슬래시가 들어가 "Zip file contains path with invalid characters"로 거부된다. 2026-09-22 확인). 스킬 파일을 고친 뒤에는 `python dist\make_zips.py`를 다시 돌린다.

방법: claude.ai 웹 → 프로필 → 설정 → 기능(Capabilities) → 스킬 → "스킬 업로드" → zip 선택. 같은 이름의 스킬이 이미 있으면 먼저 지운다 (같은 이름을 두 개 두면 어느 쪽이 실행될지 알 수 없다). 업로드 후 목록에 `brief-deliver`, `brief-prep`, `notion-store`, `weekly-report`, `work-intake` 다섯 개가 보여야 한다. 메뉴 이름은 앱 버전에 따라 조금 다를 수 있다.

확인: 이 세션에서 "브리핑 준비해줘"라고 하면 brief-prep이 발동하는지 본다 (작업 폴더가 `work-agent/`가 아니면 로컬 스킬은 안 잡히지만, 계정 스킬은 어디서나 잡힌다).

## 2. 커넥터 두 개가 살아 있는지 확인한다 (2분)

claude.ai → 설정 → 커넥터 (https://claude.ai/customize/connectors)

- **Notion**: 연결됨. 워크스페이스 "CTR Documentation", 페이지 "업무 에이전트"에 접근 권한이 있어야 한다.
- **PlayMCP (카카오)**: 연결됨. 카카오 로그인이 풀리면 06:00 작업이 "세션 만료"로 실패한 뒤 재시도도 실패한다. 한 달에 한 번쯤 여기서 상태를 본다.

## 3. 예약 작업 두 개를 등록한다 (15분)

Cowork 데스크톱 앱 → 예약 작업(Scheduled tasks) → 새로 만들기. 두 개를 따로 만든다.

| 항목 | 05:00 브리핑 | 06:00 전달 |
|---|---|---|
| 이름 | 업무 브리핑 05:00 | 브리핑 전달 06:00 |
| 일정 | 월~금 05:00, 시간대 **Asia/Seoul** | 월~금 06:00, 시간대 **Asia/Seoul** |
| 프롬프트 | `scheduled-tasks\brief-0500.md`의 `---` 아래 전부 붙여넣기 | `scheduled-tasks\brief-0600.md`의 `---` 아래 전부 붙여넣기 |
| 커넥터 | Notion | Notion, PlayMCP |
| 스킬 | brief-prep, weekly-report, notion-store, work-intake, morning | brief-deliver, notion-store |

주의 세 가지.

- 시간대를 UTC로 두면 05:00이 오후 2시에 돈다. 반드시 Asia/Seoul을 고른다. 시간대 선택이 없고 UTC만 되는 화면이면, 05:00 KST = **전날 20:00 UTC**, 06:00 KST = **전날 21:00 UTC**이고 요일은 일~목이 된다 (cron으로 쓰면 `0 20 * * 0-4`, `0 21 * * 0-4`).
- 프롬프트 안의 `{{today}}`는 예약 작업이 날짜를 넣어 주는 자리다. 그런 기능이 없으면 그 자리를 "오늘 날짜(KST)로 판단한다"로 바꿔 넣는다.
- 06:00 작업 프롬프트는 카카오톡 1통만 보내게 돼 있다. 프롬프트를 줄이거나 바꿀 때 이 문장을 지우면 안 된다.

**대안: claude.ai 루틴(Routines)으로 등록.** Cowork 예약 작업 대신 https://claude.ai/code/routines 에서 클라우드 루틴으로 만들 수도 있다. 이 경우 Claude가 이 세션에서 대신 만들어 줄 수 있다 (RemoteTrigger). 단 루틴은 클라우드 샌드박스에서 git 저장소를 받아 돌기 때문에 `work-agent/` 폴더를 GitHub 비공개 저장소에 올려 두거나, 스킬 내용을 프롬프트에 직접 넣어야 한다. 원하면 이 방식으로 바꾸자고 말하면 된다.

## 4. 낮에 한 번 수동으로 돌려 본다 (10분, Phase 0 검증)

등록 직후 "지금 실행"으로 05:00 작업을 먼저 돌리고, 끝나면 06:00 작업을 돌린다. 확인할 것:

1. 노션 브리핑 DB에 오늘 날짜 페이지가 생겼는가. 송출용 요약·낭독 대본·낭독 대본 (영어) 섹션이 있는가.
2. 05:00 작업이 몇 분 걸렸는가. 50분을 넘기면 06:00 작업이 "브리핑 없음"을 보낸다 → 전달 시각을 06:30으로 옮긴다.
3. 카톡이 왔는가. 첫 호출 실패 후 재시도로 온 것이면 정상.
4. 카톡 링크가 **어제와 같은 주소**인가 (`https://claude.ai/artifact/E3iSqdG8JWaWPLuytofsMy`). 다른 주소면 원격 작업에서 같은 주소 갱신이 안 된 것이다. 동작은 하지만 매일 주소가 바뀌고 설정이 초기화된다 → 알려 주면 방식을 바꾼다.
5. 듣기 페이지에 자연 음성이 있는가. 없고 기기 음성만 있으면 원격 샌드박스에서 edge-tts 설치나 접속이 막힌 것이다 → 8.6 대안으로 간다.
6. 브리핑 페이지 맨 아래 "전달 기록"에 한 줄이 남았는가.

## 5. 휴대폰 쪽 설정 (5분)

- 카카오톡 → 나와의 채팅 → 채팅방 알림 켜기. 06:00 알림이 필요하면 방해금지 모드 예외에 카카오톡을 넣는다.
- 듣기 페이지를 사파리/크롬에서 열어 로그인하고 **즐겨찾기 또는 홈 화면에 추가**. 카톡이 안 와도 여기서 열린다.
- (선택) iPhone: 설정 → 손쉬운 사용 → 콘텐츠 말하기 → 음성 → 한국어 → 유나(프리미엄) 내려받기. 기기 음성 예비 재생기의 품질이 올라간다. 자연 음성(선히·인준·Jenny·Guy)은 이 설정과 무관하게 항상 같다.

## 6. 결정할 것 두 가지

- 낭독 대본의 고객사명: 지금은 Z사·G사(영어는 customer Z)로 나간다. 듣기 불편하면 "고객사명 허용, 공급사명만 이니셜"로 바꿀 수 있다.
- MRO·일반자재, 유류·포장재 프로젝트의 과거 이력을 노션으로 이관할지. 지금은 로그가 0건이라 브리핑에 안 나온다.
